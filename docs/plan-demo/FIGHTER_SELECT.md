# ВЫБОР БОЙЦА и «Быстрая сборка»

Экран перед боем: игрок берёт готового бойца, свою сборку, бросает кубик или отвечает на три вопроса — и сразу в бой.
Выбранный чертёж уходит в бой единственным путём режимов — `ModeRun.launch(def, {player_blueprint: bp})` → `ModePlayer.swap_p1`.
«Обычный» (`null`) — кукла режима без подмены, как было до экрана.
Карточка **«Нарисуй»** (клавиша D) — боец из эскиза мышью: `SKETCH_FIGHTER.md`.

Снимки (1920×1080, поверх гаража) — `docs/plan-demo/fighter_select/`:

| | RU | EN |
|---|---|---|
| ростер, выбран кит «Человек» | `ru_roster.png` | `en_roster.png` |
| сборка «Тяжёлый · Голова · Поршень» | `ru_builder_heavy_head_piston.png` | `en_builder_heavy_head_piston.png` |
| сборка «Быстрый · Кистень · Лишние руки» | `ru_builder_fast_flail_arms.png` | `en_builder_fast_flail_arms.png` |

Переснять: `GODOT_BIN=/usr/local/bin/godot godot/tools/godot_bg.sh --path godot --resolution 1920x1080 --fixed-fps 60 res://tests/fighter_select_snapshot.tscn -- out_dir=<абсолютный путь>`
(разрешение именно 1920×1080: godot_bg рисует в SubViewport без растяжения).

## Где открывается

| Откуда | Что происходит |
|---|---|
| Гараж → **БЫСТРЫЙ БОЙ** (`garage_menu.gd`, `state = "pick"`) | экран поверх гаража; выбор → `ModeRun.launch(ModeCatalog "duel_classic", {player_blueprint})`, «Обычный» → старая сцена купола как раньше. Esc — назад в меню гаража на тот же пункт. `pick_fighter = false` — сразу в купол без экрана. |
| **ВСЕ РЕЖИМЫ** (`test_menu.gd`), дуэльные карточки quick / ruins / workshop_arena / void / scrap | выбор → карточка реестра `*_classic` с бойцом; «Обычный» → сцена режима как раньше. `pick_fighter = false` выключает. |
| **РЕЖИМЫ** реестра (`modes_menu.gd`), «Играть» | если сборки со стенда мастерской нет — экран выбора, затем `ModeRun.launch(def, …)`. Пришли из мастерской со своей сборкой — экран не показывается. |
| **Испытание** (`playground_gauntlet.gd`), кнопка «ВЫБРАТЬ БОЙЦА» на старте | без карточки «Обычный» (в испытании всегда сборка); выбранный боец важнее мастерской / кита, кнопка сборки показывает «СБОРКА: ВЫБРАННАЯ», нажатие возвращает к мастерской / киту. |

«В МАСТЕРСКУЮ» с любого экрана — `FighterPick.open_workshop`: чертёж кладётся в `FighterPick.pending_workshop`, Flow возвращает в гараж
и открывает мастерскую, гараж кладёт сборку на стенд (`WorkshopBuild.load_blueprint`, с историей — Ctrl+Z вернёт прежнюю).
В гараже то же без смены сцены.

## Экран (`scenes/menu/fighter_select.gd`, класс `FighterSelect`)

Свой `CanvasLayer` (слой 60) поверх хозяина, затемнение во весь кадр, ввод ловит сам (хозяева на это время молчат).

- **Слева — карточки** с 3D-портретами (`DollPortrait`; без окна — заглушка-буквы):
  - МОЙ БОЕЦ: «Обычный» (кукла режима), автосейв мастерской и сохранённые сборки (до 9, только целые), прошлая быстрая сборка,
    «Кубик», «Быстрая сборка»;
  - готовые бойцы по группам: Кит, Лига NULL, Про-лига, Аоэлюн, Наборы, Шаблоны (сейчас 33; пустые заготовки и сборки, не
    проходящие `CraftEdit.friendly_errors` в текущем режиме энергии, не показываются).
- **Справа — выбранный**: портрет, масса, энергия (занято / бюджет), число деталей, запас ❤ (если включён «запас из деталей»),
  на чём ЛКМ; кнопки **В БОЙ** и **В МАСТЕРСКУЮ**.
- Экран открывается на прошлом выборе за сессию (`FighterPick.last`).

### Клавиши и мышь

| Где | Ввод | Действие |
|---|---|---|
| карточки | стрелки / `ui_*` (геймпад) | выбор; ↑↓ переходят между разделами, колонка сохраняется |
| | Enter | В БОЙ с выбранной (на «Быстрой сборке» — открыть конструктор) |
| | R | кубик: новая случайная сборка в карточке «Кубик», она же выбрана |
| | Q | открыть «Быструю сборку» |
| | M | в мастерскую с выбранной сборкой |
| | Esc | назад (сигнал `cancelled`) |
| | клик | выбрать; клик по уже выбранной — в бой |
| конструктор | ↑↓ | вопрос |
| | ←→ или 1–4 | ответ на текущий вопрос |
| | N | ещё вариант (те же ответы, следующий seed) |
| | R / Enter / M | кубик / в бой / в мастерскую — как на карточках |
| | Esc | к карточкам |
| | клик по ответу | ответ |

Сигналы: `chosen(bp)` (`null` — «Обычный»), `cancelled`, `workshop_requested(bp)`.

## «Быстрая сборка» — как ответы становятся деталями (`scripts/body/quick_build.gd`, `QuickBuild`)

Три вопроса, по умолчанию «Средний · Кулаки · Броня»:

| Вопрос | Ответ | Что ставится |
|---|---|---|
| СТИЛЬ | Быстрый | лёгкие ядро (ящик, игрушка), голова, тонкие / костяные конечности, лёгкие стопы и кисти; цепь кистеня 1 звено |
| | Средний | бочка / барабан / клетка / торс человека, базовые / изогнутые / пружинные конечности; цепь 1 звено |
| | Тяжёлый | котёл / реактор / гироскоп, толстые / пластинчатые / роботизированные конечности, тяжёлые кулаки; цепь 2 звена |
| ЧЕМ БИТЬ | Кулаки | тяжёлые кулаки на обеих руках, ЛКМ — правая рука |
| | Голова | ударная голова (рогатая / дьявол / охотник…) + рога или шипы на Top, кисти мягкие, ЛКМ — голова |
| | Оружие | навершие (меч, топор, кирка, молот, бур…) на конце правой руки, иногда и левой, ЛКМ — предплечье |
| | Кистень | цепь / трос со свободным шарниром, на конце булава / якорь / факел; ЛКМ — рука с цепью |
| ОСОБЕННОСТЬ | Поршень | ударная деталь на поршне (у головы — правая стопа) + поршневые плечи; удар выстреливает по клавише канала |
| | Ротор | маховик на спине ядра, мотор в плече ударной руки |
| | Лишние руки | ещё пара рук на боковых якорях ядра (левая остаётся всегда) |
| | Броня | щитки и наручи на якорях Deco конечностей (хотя бы один остаётся всегда) |

- Сборка только через API мастерской (`CraftEdit.set_root`, `check` + `_apply_attach`, `set_joint`, `set_control`) — те же проверки
  вида детали, якоря и структуры, что и руками.
- Вариант = seed: `hash([стиль, удар, особенность, seed])`. Экран берёт случайный `_seed_base` при открытии, «Ещё вариант» — `+1`;
  поэтому те же ответы снова дают другую сборку, а один и тот же seed — ту же.
- Энергия сверяется целиком в конце (`BodyBlueprint.energy_cap` — в «запасе из деталей» и без него). Не влезло — снимаются
  необязательные детали (рога, броня сверх первой, правая лишняя рука), потом новый бросок. После 2/3 из 24 попыток — уступка 1
  (средние ноги, одно звено цепи, без мотора в плече), последние 4 — уступка 2 (тонкие ноги и плечи). С «запасом из деталей»
  уступки не нужны (тяжёлое ядро даёт больше энергии); без него — в 81 из 288 сборок пробы.
- Кубик (`FighterPick.roll`) — случайные ответы + случайный seed через тот же генератор.

## Данные (`scripts/modes/fighter_pick.gd`, `FighterPick`)

`roster()` — готовые бойцы из `CraftEdit.BODY_PRESETS` по группам; `my_builds()` — автосейв и сохранённые; `roll(rng)` — кубик;
`summary(bp)` — строка «масса · энергия · детали» (или «кукла режима»); `last` — прошлый выбор; `open_workshop(tree, bp)`.

## Пробы

`godot --headless --path godot --fixed-fps 60 res://tests/fighter_select_probe.tscn [-- only=data|builder|ui|spawn,dice_n=50,spawn_s=5]`

| Часть | Проверки |
|---|---|
| data | `roster_size` (≥ 20), `roster_groups`, `roster_valid`, `roster_no_empty_templates`, `dice_valid` (50 бросков), `dice_varied` (≥ 90 % разных) |
| builder (с «запасом» `_hp` и без `_nohp`) | `builder_all_valid` (48 сочетаний × 6 вариантов), `builder_hitter_seen` (ЛКМ / навершие / цепь по ответу), `builder_special_seen` (поршень / маховик / руки / броня по ответу), `builder_variants` (≥ 3 разных из 6), `builder_heavy_heavier` (масса fast < balanced < heavy); `builder_answer_changes_bp` |
| ui | `ui_full_screen`, `ui_cards`, стрелки, Enter, R, Q, N, 1–4, Esc, M, клики (`ui_*`) |
| spawn | `spawn_reaches_p1_and_lives`: весь ростер + выбранные с экрана + 10 бросков кубика уходят через `ModeRun.launch(player_blueprint)` в дуэль с ботом, P1 — `ModularDoll` с той же сигнатурой чертежа, жив через 5 с; `spawn_from_screen` |

Ещё покрывают экран: `garage_menu_probe` (`quick_opens_fighter_select`: БЫСТРЫЙ БОЙ → экран, Esc → меню), `flow_probe`
(`quick_opens_fighter_select`, затем Enter → купол), `modes_screen_probe` (`modes_click`: клик → экран → Enter → запуск),
`i18n_layout_probe` (`fighter_select:roster`, `fighter_select:builder` на всех языках).
