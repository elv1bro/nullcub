# RAGDOLL MASTER v2 — кооперативный physics roguelite (концепция автора, получена 28.09.2026)

Разворот от `CONCEPT.md` (PvP party-файтинг): главный режим теперь PvE-экспедиция на 1–4 игроков со сборкой собственного тела. `CONCEPT.md` остаётся источником по бою (урон, стан, KO, камера, лицо), этот файл — по режимам, прогрессии и сборке тела. Лор и связь лора с механикой — `LORE.md`.

## Решения автора (28.09.2026, после обсуждения)

- **PvP = «Быстрая игра»**: выбор карты → файтинг, как сейчас (Match, HUD, sudden death, медали остаются здесь). Забег настраивается отдельно, в том числе можно ли в нём драться друг с другом (friendly fire вкл/выкл).
- **Мы летаем, а не ходим.** Управление — сила на центр тела (Ядро/торс), конечности болтаются следом. Поэтому топология тела не важна: ноги — это масса, рычаг и ударные точки, а не опора. «Паук устойчивее» не является целью.
- **Лицо — наклеенная фотография:** сфоткался, лицо вырезается и клеится на голову. Это же ответ лора на загадку «зачем голова» (`LORE.md`).
- **Инвентарь до 3 слотов** для спецпредметов; главный из них — Ядро товарища, которое надо донести до верстака для возрождения.
- **Пышного финала с выбором нет.** Вершина Башни — локация, а не катсцена.
- **Уровни Башни** — 10 биомов в `BIOMES.md`, порядок может меняться. Автор пришлёт листы ассетов, по ним строим 3D.
- Следствия для кода (сверка 28.09): тяга сейчас `MOVE_FORCE_PER_KG × total_mass` (ускорение не зависит от массы) — для §7 нужна фиксированная тяга Ядра; `MASS_CAP` в `damage.gd` режет выгоду от тяжёлой головки молота; `BODY_MULT` по имени части должен стать свойством детали; сборка тела из деталей по чертежу — рантайм-поведение (исключение из правила «ничего не собирать в `_ready()`»: детали остаются `.tscn` с точками крепления).
- **Порядок:** сначала две пробы поверх текущего демо — (1) 4–5 пресетов тела без UI в площадке против обычной куклы, (2) 2 типа PvE-врагов на основе бота-наскока из `tests/match_probe.gd`, волна 3–5 против одного игрока. Если обе «да» — переписываем план (08 → враги, 07 → крафт молота, новый этап сборки тела, забег из 3 арен с боссом).

## Исходный текст автора

### Основная идея

Ragdoll Master — кооперативный 2.5D physics roguelite для 1–4 игроков.
Главный режим игры — PvE-экспедиция.
Игроки управляют физическими ragdoll-куклами, проходят последовательно генерируемые арены и комнаты, сражаются с физическими противниками, собирают детали, материалы и оружие, а между боями постепенно перестраивают собственное тело и создают уникальное оружие.
Каждая экспедиция начинается практически с нуля и постепенно превращает обычных деревянных кукол в совершенно безумные физические конструкции.

В конце одного забега персонаж может выглядеть как обычный человек с мечом. В другом:

- четыре ноги;
- одна огромная рука;
- маленький корпус;
- тяжёлая металлическая голова;
- цепь вместо второй руки;
- самодельная булава с гвоздями.

При этом это не просто визуальная кастомизация. Каждая установленная деталь физически меняет поведение персонажа.

### 1. Основной игровой цикл

Базовый цикл:
МАСТЕРСКАЯ → БОЙ → LOOT → МОДИФИКАЦИЯ → ВЫБОР ПУТИ → БОЙ → … → BOSS → HOME

В первой версии для проверки идеи путь можно максимально упростить:
ARENA → LOOT → CRAFT → ARENA → LOOT → CRAFT → ARENA → BOSS

Если этот цикл работает и уже сам по себе интересен, позже отдельные арены объединяются в полноценный процедурно генерируемый мир.

### 2. Начало экспедиции

Игрок или группа игроков появляется в небольшой мастерской. Здесь находятся их куклы.
Перед началом можно выбрать:

- цвет;
- лицо;
- базовую голову;
- косметику;
- сохранённые визуальные настройки.

Но игровой персонаж начинает относительно простым. Например: голова + корпус + две руки + две ноги.
Минимальное стартовое оружие либо отсутствует, либо выбирается из нескольких очень простых вариантов.
После этого игроки открывают ворота: START EXPEDITION. И начинается первая арена.

### 3. PvE как основной режим

Главный противник игрока — не другой игрок, а мир. Игроки вместе сражаются против:

- обычных ragdoll-врагов;
- вооружённых врагов;
- быстрых маленьких существ;
- тяжёлых противников;
- летающих конструкций;
- ловушек;
- механизмов;
- мини-боссов;
- огромных физических боссов.

Все противники подчиняются той же физической системе. Их можно:

- сбивать;
- толкать;
- раскручивать;
- сталкивать с платформ;
- прижимать предметами;
- отправлять в полёт;
- сталкивать друг с другом;
- использовать части окружения против них.

### 4. Главное отличие — игрок строит собственное тело

Тело персонажа состоит из физических модулей. Есть базовый CORE / TORSO. На нём находятся заранее определённые Anchor Points.
Например HEAD — это специальный anchor, на нём всегда должна находиться голова. Но остальные anchors значительно свободнее.

```text
        HEAD
         ●
         │
    ●── CORE ──●
        ●   ●
```

Каждая деталь сама может содержать дополнительные anchors. Например рука:

```text
CORE
 │
 ● ARM
     │
     ●
```

На её конец можно установить:

- кисть;
- другую руку;
- оружие;
- ногу;
- дополнительный сустав;
- другую совместимую деталь.

Поэтому структура тела может продолжать разрастаться.

### 5. Не существует обязательной человеческой формы

И это принципиально важно. Игра не говорит: «сюда можно поставить только левую руку». Она говорит: «здесь находится универсальный физический anchor». Поэтому игрок может сделать:

```text
       🙂
        │
     ──BODY──
      / | \
     🦵 🦵 🦵
       / \
      🦵 🦵
```

Получится своеобразный паук. Или:

```text
       🙂
        │
   ARM-BODY-ARM-ARM
       │
      LEG
```

Или персонажа практически без ног, но с огромными руками. Можно экспериментировать.

### 6. Ограничение — ENERGY

Чтобы игрок не мог просто поставить 50 конечностей, существует общий энергетический бюджет. Например: CORE ENERGY: 100.
Каждая деталь потребляет энергию. Пример:

| Деталь | Energy |
|---|---|
| Small Arm | 10 |
| Heavy Arm | 18 |
| Leg | 15 |
| Additional Joint | 5 |
| Metal Head | 20 |
| Motorized Joint | 25 |
| Shield | 12 |

Игрок может построить простое сильное тело или сложную конструкцию с большим количеством маленьких деталей. Это создаёт настоящую систему билдов.

### 7. Масса тоже имеет значение

Energy не является единственным ограничением. У каждой детали есть: масса; размер; прочность; friction; joint strength; energy cost; физическая форма.

Поэтому можно сделать огромного персонажа. Но огромный персонаж: тяжелее разгоняется; медленнее меняет направление; сильнее ударяет; сложнее отправляется в полёт.
Маленький: быстро ускоряется; легко вращается; далеко улетает; слабее при прямом столкновении.
Это позволяет создавать очень разные физические билды.

### 8. Тело становится частью оружия

У персонажа нет строгого разделения BODY / WEAPON. Например игрок может поставить тяжёлый металлический шар вместо кисти — теперь сама рука является булавой.
Или: цепь → рука → топор. Получается огромный физический flail.
Или: длинная рука → длинная рука → молот. Очень сложно контролировать. Но если раскрутить — ОГРОМНЫЙ IMPACT.
Поэтому игрок фактически проектирует собственную физическую машину.

### 9. Крафт оружия

Отдельно существует система оружия. После боёв игрок получает материалы: дерево; железо; гвозди; цепи; камень; ткань; верёвки; редкие материалы.
Можно найти готовый молот. Но затем его можно изменить. Например WOODEN HAMMER:
добавляем 6 NAILS — получаем физические шипы; добавляем IRON PLATE — головка становится тяжелее; добавляем LONG HANDLE — меняется длина рычага.
Теперь это совершенно другое оружие.

### 10. Крафт должен менять физику, а не цифры

Это один из главных принципов игры.
Плохой вариант: Epic Hammer: +20% Damage.
Хороший вариант: ты физически сделал головку молота тяжелее. Поэтому: центр массы сместился; оружие медленнее раскручивается; сложнее остановить движение; попадание значительно сильнее.
То есть характеристики являются следствием конструкции.

### 11. Loot

После каждого боя игроки получают новые возможности. Например CHEST. Открываем:

```text
IRON ARM
CHAIN x2
NAILS x8
LONG WOODEN HANDLE
LIGHT JOINT
```

И теперь появляется вопрос: что из этого построить?

### 12. Между аренами — мастерская

После боя игроки попадают в короткую безопасную комнату. Там можно:
REPAIR — починить повреждённые детали; BODY — перестроить персонажа; CRAFT — изменить оружие; STORAGE — оставить ненужные материалы.
Это должно занимать не десять минут работы в сложном редакторе. Интерфейс должен быть почти игрушечным: взял деталь → поднёс к anchor → CLICK → установлено.

### 13. Получается emergent progression

Например игрок начал:

```text
🙂
│
BODY
/  \
LEG LEG
```

После первого боя нашёл дополнительную руку. Поставил её сбоку. После второго нашёл ещё две ноги. Получилось:

```text
      🙂
       │
ARM──BODY──ARM
    / | | \
   🦵 🦵 🦵 🦵
```

После третьего боя нашёл цепь. Снял руку. Сделал: BODY → ARM → CHAIN → HAMMER.
После пятого боя его персонаж уже совершенно не похож на стартового. Это и становится историей конкретного забега.

### 14. Арены

Для MVP не нужно сразу делать огромный procedural castle. Сначала:
ARENA 1 (простая тренировочная территория) → LOOT → WORKSHOP → ARENA 2 (больше вертикальности) → LOOT → WORKSHOP → ARENA 3 (ловушки и сложные противники) → MINI BOSS → WORKSHOP → FINAL BOSS.
Этого достаточно, чтобы проверить главный цикл.

### 15. Будущее — вертикальный замок

Если система работает, отдельные арены превращаются в части одного огромного процедурного сооружения. Например:

```text
                👑 THRONE
                   │
             ┌─────┴─────┐
          ARMORY       LABORATORY
             │             │
          TOWER          PRISON
             │             │
             └─────┬───────┘
                COURTYARD
                    │
                 SEWERS
                    │
                 ENTRANCE
```

Но игрок не выбирает это из меню. Он физически путешествует по миру.

### 16. Генерация замка

Замок собирается из заранее созданных комнат. Например существует 50–100 room modules. Игра генерирует: порядок; соединения; врагов; loot; ловушки; модификаторы; секретные помещения; события.
Поэтому каждая экспедиция отличается.

### 17. Вертикальность

Замок желательно строить преимущественно вертикально. Это идеально подходит механике полётов. Игрок может получить удар 💥 и улететь вниз через несколько уровней:

```text
ARMORY
────────────
       🤸
       ↓
LIBRARY
────────────
       ↓
PRISON
────────────
       💥
```

И теперь игрок реально оказался в другой комнате. Враги могут последовать за ним. Получается непрерывное приключение, а не последовательность изолированных арен.

### 18. Разрушаемые маршруты

Физика может сама создавать новые пути. Например игрок получает мощный удар, влетает в старую стену — CRASH — стена рушится, за ней SECRET ROOM. Или игрок ломает пол — вся команда падает на этаж ниже.
Так физическая механика становится частью исследования мира.

### 19. Комнаты

Не каждая комната должна быть боевой:

| Комната | Суть |
|---|---|
| BATTLE | обычный бой |
| ELITE | очень сильные враги |
| FORGE | редкий крафт |
| SCRAP ROOM | много материалов |
| SHOP | покупка деталей |
| EVENT | неизвестное событие |
| TRAP | физическое испытание |
| TREASURE | редкий loot |
| BOSS | большой физический противник |
| SECRET | скрытая комната |

### 20. Боссы

Боссы особенно интересны из-за системы физики. Это не просто враг на 10000 HP. Например огромный деревянный рыцарь: две огромные ноги; руки; броня; физические joints.
Игроки могут буквально разбирать босса. Сломали левую ногу — он начинает хромать. Оторвали руку — его меч падает. Игрок может подобрать меч босса. Четыре игрока пытаются вместе использовать огромный меч. И начинается полный хаос.

### 21. Кооперация

PvE рассчитан на 1–4 игроков. Конструкции игроков могут дополнять друг друга:
Tank — огромный тяжёлый корпус; Spinner — лёгкий персонаж с длинным оружием; Spider — шесть ног, отличная устойчивость; Glass Cannon — огромная рука с молотом, маленькое тело.
При этом никаких фиксированных классов нет. Игроки сами случайно изобретают классы через строительство тела.

### 22. Дружеский хаос

Даже в PvE физические столкновения между друзьями желательно сохранить. Не обязательно полный friendly damage. Но друзья могут: толкнуть друг друга; случайно отправить товарища в полёт; зацепиться оружием; столкнуться; уронить предмет.
Это сохраняет party-game составляющую.

### 23. PvP

PvP существует отдельно. Например ARENA: 1v1 / 2v2 / FFA. Игроки могут использовать созданных персонажей. Но желательно иметь два варианта:
CUSTOM — всё разрешено; BALANCED — всем выдаётся одинаковый Energy Budget и доступный набор деталей.
Так PvP не начинает диктовать баланс всей PvE-игры.

### 24. Долгосрочная прогрессия

Между экспедициями игрок не должен просто бесконечно получать +5% Damage. Лучше открывать: новые детали; новые типы joints; новые материалы; новые свойства; новые головы; новые cosmetic элементы; новые room types; новые биомы; новые возможности крафта.
Игрок получает больше вариантов, а не просто становится математически сильнее.

### 25. Домашняя мастерская

Между экспедициями существует постоянное пространство игрока — его мастерская. Там хранятся: трофеи; созданное оружие; головы боссов; лучшие конструкции; фотографии; медали; редкие материалы; лучшие replay.
Друг может зайти в мастерскую и увидеть легендарную абсолютно идиотскую восьминогую куклу, которой вы победили босса неделю назад. Это создаёт эмоциональную историю игры.

### 26. Что генерируется каждый раз

Каждая экспедиция получает новый seed. Он определяет:
WORLD — комнаты; маршруты; арены; биомы.
COMBAT — врагов; группы противников; элитных врагов; боссов.
LOOT — детали тела; оружие; материалы; редкие компоненты.
EVENTS — ловушки; события; секретные комнаты; модификаторы.
Поэтому нельзя заранее знать, какой персонаж получится к концу экспедиции.

### 27. Главная фантазия игрока

Игрок начинает экспедицию обычной деревянной куклой. Через 40 минут перед финальным боссом стоит четырёхногий деревянно-металлический монстр с тремя руками, металлической головой и огромным самодельным молотом на цепи.
И самое важное: игрок сам построил его из того, что нашёл по дороге.

### 28. Основная формула

EXPLORE → FIGHT → BREAK → LOOT → BUILD → MUTATE → GO DEEPER
И снова: FIGHT → LOOT → BUILD → MUTATE — до тех пор, пока команда не доберётся до вершины.

### 29. Что делать прямо сейчас

Полноценный процедурный вертикальный замок пока НЕ делать. Первый прототип должен проверить только три фундаментальные системы:

1. **PHYSICS COMBAT** — два-три типа PvE-врагов; управление центром массы; удары конечностями; полёты; физическое оружие.
2. **BODY BUILDER** — один Core; голова; рука; нога; несколько универсальных anchors; возможность поставить ногу вместо руки, руку на руку, четыре ноги, оружие на конец конечности; Energy Budget.
3. **CRAFTING** — молот; рукоять; металлическая головка; гвозди; цепь; и физическое изменение параметров после модификации.

После этого собрать маленький забег: ARENA 1 → LOOT → BUILD → ARENA 2 → LOOT → BUILD → BOSS.
Если уже на этом этапе появляется ощущение «Смотри, какую хрень я собрал. Сейчас попробую ей победить босса» — значит ядро Ragdoll Master найдено.
А уже следующим этапом эту последовательность арен можно превратить в огромный генерируемый вертикальный замок с комнатами, развилками, секретами и падениями между этажами.
