# Сборка тела, крафт оружия, рука мышью, захват — контракт v1 (28.09.2026)

Общий контракт для всех, кто делает эти системы. Замысел — `CONCEPT_V2.md` §4–13, лор — `LORE.md`. Код — только в новых файлах: `scenes/doll/doll.gd`, `scripts/tuning.gd`, `scripts/core/*`, `scenes/playground.gd`, `project.godot` сейчас правит другая сессия (feel куклы v6–v7), их не трогаем — нужные хуки перечислены в конце.

## Решения автора (28.09)

1. **Одна система деталей для тела и оружия** («тело становится частью оружия»): деталь → точки крепления → чертёж.
2. **Рука мышью.** В чертеже помечается 1 деталь (позже 2), которой игрок дополнительно управляет: пока зажата ЛКМ, деталь **мягко** тянется к курсору (курсор уже в плоскости боя). Отпустил — снова болтается. Геймпад — правый стик.
3. **Захват — отдельная клавиша-переключатель:** нажал — управляемая деталь схватила ближайший предмет, нажал ещё раз — отпустила. Бросок = отпустить на замахе.
4. **Разный вес предметов:** лёгкие (≤ 15 кг) летят далеко, средние (15–40) можно тащить и раскачивать, тяжёлые (≥ 80) схватить можно, но почти не сдвинуть.
5. **Порядок:** система сборки + пресеты → рука и захват (параллельно) → мастерская (сборка мышью, крафт оружия) → Свалка v2 (простор + механизмы + лут).

## 1. Деталь (PartDef + сцена)

**Ресурс** `scripts/body/part_def.gd` (`class_name PartDef extends Resource`), файлы `data/body/parts/<id>.tres`:

| Поле | Смысл |
|---|---|
| `id` | `wood_upper_arm`, `junk_head_sad`, `iron_ball_hand`, `handle_long`, `nails` … |
| `title` | подпись в мастерской (рус.) |
| `kind` | `core` · `head` · `limb` · `hand` · `foot` · `joint` · `handle` · `weapon_head` · `mod` · `chain` · `plate` |
| `scene` | PackedScene детали (`scenes/body/parts/<id>.tscn`) |
| `mass` | кг (пишется в RigidBody3D) |
| `energy` | стоимость в бюджете Ядра |
| `attach` | `joint` (свой RigidBody + сустав) или `fixed` (сливается с родителем: формы и меш переезжают в тело родителя, масса и центр масс пересчитываются) |
| `body_mult` | множитель урона этой частью как бьющей (вместо таблицы по имени; пока дублируем в имя, см. §3) |
| `material` | `wood` · `iron` · `cloth` (магнит и звуки потом) |
| `name_prefix` | префикс имени тела в собранной кукле: `UpperArm`, `LowerArm`, `Hand`, `UpperLeg`, `LowerLeg`, `Foot`, `Head`, `Torso`, `Chain`, `Handle` … |

**Сцена детали** `scenes/body/parts/<id>.tscn`: корень `RigidBody3D` (коллизии `Shape*`, меш `Mesh`), плюс маркеры:

- `Socket` (Marker3D) — точка, которой деталь крепится к родителю (проксимальный сустав). Его **−Y** смотрит туда, куда деталь «растёт» от родителя. У руки — вниз вдоль кости, у головы — вверх.
- `Anchor_<имя>` (Marker3D) — куда можно крепить детей: позиция = точка сустава, **−Y** = направление, куда вырастет ребёнок. Метаданные маркера:
  - `accepts`: PackedStringArray видов (`limb`, `hand`, `foot`, `head`, `weapon_head`, `mod`, `chain`, `handle`…);
  - `joint_group`: группа мышц сустава, который здесь создастся (`Shoulder`, `Elbow`, `Wrist`, `Hip`, `Knee`, `Ankle`, `Neck`);
  - `rest_deg`: угол покоя сустава по умолчанию;
  - `mirror`: true для правой стороны.
- Посадка ребёнка: `child.global_transform = anchor.global_transform * child_socket.transform.affine_inverse()`.
- Всё в плоскости XY (z = 0), лицо к камере (+Z), как у куклы v3.

**Свободный шарнир** (цепь, кистень) — группа `Ankle`: у неё k = 0, работает только трение. Своей группы `Free` в `Tuning.MUSCLE_GROUPS` нет, а `tuning.gd` не наш.

## 2. Чертёж (BodyBlueprint)

`scripts/body/body_blueprint.gd` (`class_name BodyBlueprint extends Resource`), пресеты — `data/body/blueprints/<id>.tres`:

- `title`, `energy_budget` (100);
- `nodes`: массив словарей `{uid, part, parent, anchor, rest_deg?, name?}`:
  - `uid` — ОДИН символ `0-9A-Z` (урон режет суффикс имени только длиной ≤ 1 символа: `UpperArm_3`, но не `UpperArm_12`, см. `Damage.body_mult_of`);
  - `part` — id PartDef;
  - `parent` — uid родителя (у ядра пусто);
  - `anchor` — имя Anchor_* у родителя;
  - `rest_deg` — переопределение угла покоя;
  - `name` — явное имя тела, нужно для пресета «человек»;
- `control` — массив uid деталей, которыми управляет рука мышью (сейчас ≤ 1, позже ≤ 2);
- `weapon` — необязательный WeaponBlueprint на указанной детали (§4).

Правила: корень — ядро (`Torso`), ровно одна деталь вида `head` на якоре `Anchor_Neck` ядра (лор: голова обязательна). Сумма `energy` ≤ `energy_budget`. Имена тел — `<name_prefix>_<uid>`, суставов — `<joint_group>_<uid>`. Пресет `human` использует явные имена куклы (`UpperArm_L`, `Shoulder_L` …), чтобы feel и урон совпадали с `doll.tscn`.

## 3. Модульная кукла (ModularDoll)

`scripts/body/modular_doll.gd`: `class_name ModularDoll extends Doll`, `@export var blueprint: BodyBlueprint`. В `_ready()`:

1. собрать детей по чертежу — инстансы сцен деталей, посадка по Socket/Anchor, `Generic6DOFJoint3D`, настроенные как в `doll.tscn` (линейные оси заперты, вращение только вокруг Z, лимиты, мотор-трение `friction_factor` по группе), fixed-детали слиты с родителем;
2. вызвать `super._ready()`: Doll сам находит тела и суставы по дереву и навешивает мышцы по префиксу имени сустава;
3. применить углы покоя чертежа через `set_pose({имя_сустава: градусы})`, переопределить `reset_pose()`, чтобы он возвращал позу чертежа, а не `Tuning.POSE`.

Тяга: сейчас `MOVE_FORCE_PER_KG × total_mass` — тяжёлый разгоняется как лёгкий. Концепту нужна фиксированная тяга Ядра (тяжёлый медленнее). В v1 решить внутри подкласса, если `total_mass` больше нигде не значит «настоящая масса» (проверить все использования), иначе — хук в §6.

## 4. Крафтовое оружие

Оружие — такой же чертёж деталей (рукоять → головка → моды), но собирается в **`Weapon`** (`scenes/weapons/weapon.gd`), чтобы работали подбор `WeaponPickup`, урон вида weapon, зачёт брошенного оружия и статистика:

- `scripts/body/weapon_blueprint.gd` (`class_name WeaponBlueprint extends Resource`): `nodes` как у тела, корень — `handle`;
- `scripts/body/crafted_weapon.gd` (`class_name CraftedWeapon extends Weapon`): fixed-детали сливаются в одно тело (составные коллизии, масса = сумма, центр масс настоящий, `grip_local` = хват рукояти, `length` = габарит), цепь — отдельные тела на свободных шарнирах (кистень);
- `damage_mult` — от головки и модов (лезвие, шипы), масса и длина — от конструкции. Урон уже ∝ масса × скорость. Но `Tuning.MASS_CAP` = 4 кг режет выгоду от тяжёлой головки: это хук §6.

## 5. Рука мышью и захват

`scripts/body/arm_assist.gd` (`class_name ArmAssist extends Node`, ребёнок куклы, как `WeaponPickup`):

- **Какая деталь управляется.** `control_part` — имя тела; у ModularDoll берётся из `blueprint.control`, у обычной куклы по умолчанию `Hand_R`.
- **Ввод.**
  - p1: ЛКМ зажата → цель = курсор в плоскости z = 0 (луч камеры × плоскость);
  - геймпад: правый стик → цель = деталь + стик × радиус досягаемости.
  - Действия создаются в InputMap во время работы (`InputMap.add_action`), если их нет: `project.godot` не трогаем.
- **Сила «мягкой помощи».**
  - Формула: F = clamp(k·(цель − деталь) − c·v, F_max).
  - Прикладывается к детали и **−F к торсу**: сумма ноль, рукой нельзя «грести» и летать.
  - Досягаемость ограничена длиной цепи. Отпустил — сила ноль.
  - Числа — константы в скрипте с комментарием (в `tuning.gd` не пишем).
- **Захват.**
  - Клавиша-переключатель (p1 — свободная клавиша рядом с WASD; геймпад — RB).
  - Хватает ближайший RigidBody3D в радиусе ~0.4 м от управляемой детали, кроме своих частей: пропсы, куски хлама, чужие куклы — решить.
  - Держит суставом. Повторное нажатие отпускает.
  - Тяжёлое держится суставом с ограниченной силой: срывается или едва двигается.
- **Брошенный предмет бьёт.** До ~2 с после отпускания он засчитывается бросившему: урон через публичный `Doll.take_damage(...)` по формуле `Damage.compute` от массы и скорости предмета, вид `weapon`. Всё это — из своего компонента, без правки `doll_combat.gd`.
