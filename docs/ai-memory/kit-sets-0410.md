**04.10.2026.** Автор попросил каталог всех элементов игры, затем спросил, что добавить, чтобы игра стала «взрослее», прислал три листа-концепта (про-лига Земли / Аоэлюн / утилиты; лежат в `docs/refs/null/sets-0410-sheet*.webp`) и сказал: «давай добавлять модели в игру как детали и закрывать проблемы».

Что есть (05.10 закоммичено в main `bd9fc75` по просьбе сессии релиза 0.0.3, не запушено; `docs/catalog/` — 24 МБ картинок — в git не клал, решение автора):
- **Каталог** `docs/catalog/index.html` (21+ МБ с картинками): `godot/tools/catalog_export.tscn` (окно, через `godot_nofocus.sh`) → `python3 godot/tools/build_catalog.py <папка>`; шаблон `catalog_template.html`.
- **Наборы** `kit_pro.py` (13 деталей) и `kit_aoe.py` (12): `docs/plan-demo/KIT_SETS.md` — списки, бойцы `pro_sprinter`, `pro_titan`, `aoe_predator`, `aoe_ram`, порядок пересборки, что с листов не сделано.
- **Броня и поломка деталей:** `docs/plan-demo/ARMOR_BREAK.md`. Таблица `Tuning.PART_ARMOR`, числа стартовые — автор их ещё не играл. Поломка по материалу с 05.10 выключена (`Tuning.PART_BREAK = false`, ушло в коммит суставов `1b43adf`): автор 04.10 в соседней сессии просил пробовать отрыв деталей отдельным режимом — «Прочность суставов», клавиша C (`JOINT_BREAK.md`); какой счёт оставить — не решено.

- **Разветвители** (автор 04.10: «нужно собирать интересные невозможные конструкции»): тройник, узел-сплетение, рама-позвонок, позвонок — детали с якорями `End` + `Side_L/R`; бойцы `pro_centipede`, `pro_multitool`, `aoe_leviathan`, `set_chimera`, шаблон `open_empty` (бюджет 300). В `build_league.gd` формат `"tree"`; uid «L» и «R» запрещены (дают второй `UpperArm_L`); раздел в `KIT_SETS.md`.

**Why:** листы автора — картинки без 3D; путь «лист → скрипт Blender → кит» уже работал для деталей лиги и не нарушает правило 1 пайплайна.

**How to apply:**
- Новую партию с листов делать так же: по одному модулю `kit_<набор>.py`, каждый помощник правит только свой модуль и не запускает `--export` и Godot; проверка без экспорта — `godot/tools/blender/kit_tris.py`; экспорт и встраивание — один исполнитель.
- Сборщик `build_body_kit.gd` в `-s` портил сцены пресетов (`hud.gd` звал автозагрузку `Flow` по имени). Исправление сделано 04.10 в worktree `.claude/worktrees/vigorous-wilson-1e8724` (ветка `claude/vigorous-wilson-1e8724`, с 05.10 коммит df3559f, не запушен; вливает в main сессия релиза 0.0.3). Признак, что правка уже в чекауте: в `godot/tools/build_body_kit.gd` есть `_write_preset_scene`. Если её нет — после сборщика по-прежнему `git checkout -- godot/scenes/body/presets/`.
- Проверка «скрипт куклы скомпилирован в `-s`»: `can_instantiate()` НЕ годится (true, когда ошибка в зависимом скрипте; false только у самого скрипта с ошибкой). Рабочий признак — `get_property_default_value` возвращает null для всех свойств (проверено 04.10, Godot 4.7.2).
- В скриптах `scripts/body` и `scripts/core` не ссылаться на `CraftEdit` и прочие скрипты сцен: цепочка тянет `Flow` и ломает сборщики.
- zsh не разбивает переменную с командой на слова: вместо `G="gtimeout … godot"; $G …` писать функцию.
